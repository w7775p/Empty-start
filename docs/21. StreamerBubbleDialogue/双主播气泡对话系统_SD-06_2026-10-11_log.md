## 本次实现

Sandbox 组合 `StreamerBubbleCombatStatePresenter`，由其订阅 `BattleAttemptFlow` 与 `ContradictionOracleFlow` 的公开事实。Presenter 按稳定事件 ID 查询当前 `BubbleDialogueConfig`，复制匹配条目后设为 `PLOT` 并提交 SD-03 序列，保持配置 Resource 只读。

事件映射如下：

- T0 进入正 Tier：`combat_connected`；跨档直达 T2+ 时再提交一次 `combat_tier_up`。
- 普通升档、降档：`combat_tier_up`、`combat_tier_down`；T2+ 降至 T1 使用 `combat_tier1_taunt`；降至 T0 沿用 HUD 离线清理，不提交降档对白。
- 普通胜负：分别来自 `normal_combat_completed` 与 `attempt_failed`，映射到 `combat_win`、`combat_lose`。
- 矛盾流程结果使用 `paradox_breakthrough`、`paradox_not_broken`，与普通 PK 胜负分开。

Sandbox 新增 `dialogue_event_sequence_completed(event_id, sequence_id, side)`，在 SD-03 最后一条序列气泡实际到期后转发给 CS-23。没有配置条目时以空 `sequence_id`、`side=-1` 通知零句序列完成；重开或对手离线取消的序列不会伪报完成。同一事件的多条配置需要属于同一发言侧，以符合 SD-03 的序列契约。

正式 `bubble_dialogue_config.tres`、20 表、导出器、SD-04/05 Presenter 与 CS-22/23/27 业务代码均未修改。正式台词仍为空；验收文本只在 smoke 进程的深复制配置中创建。
