### A/D 接口与数据依赖

- 初始化：A 在发布词条和查询人口配置前调用 `PlanBContentCatalog.load_configuration()`，并检查返回 `true`。
- D 读取 `get_word_definition(word_id) -> Dictionary` 的 `battle_type: StringName`、`battle_type_emoji: String`、`tendency` / `tendency_id: StringName`；`tendency` 与 `tendency_id` 同值。`source_tendency: StringName` 保留源表值供审计，源值 `heresy` 规范为稳定 ID `heretical`。返回值为深复制快照。
- `get_type_matchup(attacker_type, defender_type) -> StringName` 只返回关系矩阵定义的 `advantage` / `disadvantage` / `same`；`battle_type_emoji.csv` 只供显示，不能改变克制结果。`get_battle_type_emoji(type_id) -> String` 可独立按类型 ID 读取占位符号。
- A/B 可通过 `get_population_config() -> Dictionary` 读取 C 候选的30个中立、C额外seed槽0、中心0.75秒与 jitter 0.25；A 仍单独提供自己的2个对手初始播种槽。
- `word_pool.csv.battle_type` 必须匹配 `battle_type_matchups.csv` 和 `battle_type_emoji.csv` 的稳定 ID；倾向显示消费 `tendency_id`。Emoji 表的 `mapping_status=pb18_provisional_engineering_placeholder` 明确它是可替换工程首值，不代表用户定稿；克制矩阵仍是战斗规则唯一来源。
