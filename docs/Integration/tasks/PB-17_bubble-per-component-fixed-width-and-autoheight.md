## 已经实现的功能
已有团体共享复读气泡：单人P1与多人P2均按人数放大，且必须完整显示原话；现有主播对白/聊天等气泡组件还有自己的布局。用户此次明确“每一种气泡有规定宽度，高度随文字增加”。

## 本次任务
### 1. 每类气泡单独确定宽度规则
1. 对当前游戏所有**气泡式文本容器**盘点真实使用实例（包括团体复读、左右主播台词及其它实际气泡）。在现有组件内分别确定**固定的类别宽度或宽度计算规则**，并以可调常量/Resource/已有配置记录。
2. **团体复读气泡继续使用 PB-11 的人数→宽度函数**，短句参考：1人约100px、2人约150px、8人约500px。当前团体人数变化才改变其**规定宽度**；相同人数、不同文本长度共用同一规定宽度。
3. 主播台词等其它类型气泡各自采用适合其展示区域的固定宽度。所有类型的宽度值应来自各自的绘制组件配置，供后续美术调整。
### 2. 文本负责高度
1. 每个气泡先确定自身宽度，然后在宽度内**自动换行、测量全文高度、计算内边距**，使气泡高度由真实话语内容和已决定的字号、行高共同决定。
2. 适度自动缩小字号和行高以保证清晰；文本始终保留**完整原句**，绘制与容器高度同步更新。气泡随文本增长的空间优先沿垂直方向扩展。
3. 使用现有 Godot 字体测量/Control 自动换行机制与布局缓存；仅在文本、成员数量（决定宽度）、字体资源变化时重新测量。团体持续移动仅平移/重绘，不每帧重新排版文字。
4. **宽度先锁定、再计算文本高度**：团体气泡按人数、主播对白按自身类别规则确定宽度；动态换行与字号/行高适配只改变高度，不因长句横向撑宽。
5. 贴近上沿/下沿时优先调整气泡展开方向与局部位置，维护原尾巴指向；与上方PK条及下方三张话语卡所在交互区做好安全边界，避免覆盖按钮或遮住主播操作信息。若最长真实句在固定宽度下确实超过单一可见区域，优先通过现有完整文本容器、字体与布局让句子全部可见，并**在Godot真实画面记录该具体文本和边界方案**；不能静默截断、显示省略号或将全文移出视野。
### 3. 与原有表现保持一致
1. PB-11 的 P1/P2轮廓、抽样1～5尾、团体级计时和事件即时触发继续工作；实时改口会更新完整话语和高度。
2. 通过不同短句、最长实际配置长句、不同人数、左右主播两侧实际渲染验证容器规则。

## 本卡验收标准（真实 Godot）
- 单人和多人团体在相同人数时宽度不随文字字数横向漂移；1、3、8人团的宽度仍按人数增长。
- 不同气泡类型分别具有自己可调的规定宽度；一句话越长，气泡能按排版结果自动增高并显示全句。
- 使用正式词库**实际最长原文**，分别在中央棋盘四角与左右主播栏截图验收：全文完整，主体不覆盖三卡操作区/PK条，尾巴指向成员；无法共存的极端布局需报告真实输入和问题，不以裁切/省略号冒充通过。
