## 已经实现的功能
当前棋子实际显示极小，甚至小于周边文字，玩家无法识别头像。上传的六张棋子贴图实测均为512×512，逻辑视觉目标128×128；当前模拟物理碰撞半径约13px，需与最新要求统一。

## 本次任务
### 1. 视觉统一到128×128（D）
1. 棋盘内所有中立、玩家和对手棋子均显示为128×128逻辑像素；保持原图比例、中心对齐、完整头像与倾向光圈。
2. 关联的描边、团体气泡、受击反馈和点击/选中提示随128px头像定位，注意棋盘边缘的可见范围。
3. 对照原本小头像与新128px真实 Godot 截图，标注对应场景及窗口分辨率。

### 2. 碰撞也统一到128×128（B）
1. 棋子用于接触、碰撞、阻挡、感染和结群的**有效物理碰撞区域统一为128×128逻辑像素**。当前模拟采用圆形半径时，设置有效半径为**64px**（外接方框128×128），使头像与物理接触中心重合。
2. 同步核对模拟邻域范围、空间网格查询、接触/感染判定、碰撞分离、出界限制、生成/随机落点及点击反馈，避免只放大图像而实际上仍使用旧13px碰撞。
3. PB-15 已确定开局30中立并持续随机入场，另有双方2/4/8批次发表。大碰撞区域可能导致局面拥挤，请用现有算法做最小调整，确保正常生成、移动和互相感染；出现容量冲突时记录根因并协调 A，不擅自退回13px旧规则。
4. 与 A 的正式战斗入口合流后，使用一次针对性真实场景验证：30人初始化、生成边界、接触感染、非接触不误判和批次发表。保留核心 PK/结群语义。

### 3. PR 截图验收（D/B/E）
1. 需要视觉验收的 PR 正文**必须直接附上真实 Godot 游戏运行截图预览**，可在 GitHub 打开，并写明实际分辨率、截图所对应提交 SHA。截图展示30名中立和128px棋子实际画面；必要时用短视频辅助说明接触、感染或动画。
2. 有画面改动时附改前/改后对照；缺少真实运行截图的视觉类 PR 保持 Draft，待验收后才能合并。
3. E 只做一次与任务直接相关的窗口验收，必要时检查帧耗时变化；禁止反复容量 sweep。

## 本卡验收标准（真实 Godot）
- 头像实际显示尺寸128×128，物理碰撞外接范围128×128（圆形半径64px），所有阵营使用一致的有效接触范围。
- 30名中立开局及后续随机补人、整批2/4/8发表仍正常；头像完整可读且相邻棋子接触/感染与外观一致。
- PR 正文附实际 Godot 截图预览及测试提交 SHA；对碰撞与感染做最小针对性验证。
