# PB-14 · 运行时性能问题跟踪清单

日期：2026-10-18；状态：证据收集阶段。**此清单不是性能优化通过证明，也不授权循环压测。**

## 目标与约束
- 先判明“正式 Plan B 一局中什么环节消耗了帧时间”，再逐项做最小代码修复。
- 只准一次短时 Headless 运行验证 Tracker 数据完整性；无窗口渲染的 Draw Calls=0 不能用于判断 D3D12。
- 后续窗口化性能定向验证应在 A Tracker 稳定、B/D/E 报告审核之后进行一次；不再按96/128/160/192反复跑人口 sweep。
- 性能优化后再定正式同屏人口上限；96 只是现有可比较样本基准，不是最终数值。

## 统一验收清单
- [ ] A 完成 opt-in `PB14_PERF_TRACKER=1`，默认禁用，关卡和正常战斗逻辑不发生变化
- [ ] 单次短跑生成含 Git SHA/场景信息、阶段、人口、3个卡位、团体/气泡计数、分段调用数和耗时的 JSONL
- [ ] 跟踪器自身文件写入至多每秒一次、帧循环无大量字典分配，不把 Headless Draw Calls 当实际 GPU 指标
- [ ] B/D/E 报告 + A Tracker 以独立 PR 提交，单独审查与合并
- [ ] 有分段耗时后按 PERF 编号一次仅修一项；记录实际 before/after，不扩展整日循环压测

## 后续数据口径
每次输出保留 `full_commit_sha`、逻辑/实际窗口大小、场景、物理 TPS、是否 Headless、候选波次/实时人口、测试时段，避免只凭日志常量判断版本。累计 section 可能互相包含：**不能直接把全部 section 耗时相加当整帧耗时**。
