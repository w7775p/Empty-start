## UI 与模拟负担的区分

- 6b384425 的 draw calls 从 pre-D 约316.6升至约618.3，GPU mean 从1.912ms升至2.122ms；D 的 [`PlanBUnitField._draw()`](/C:/Users/lvy/.codex/worktrees/fc83/Empty-start/ui/plan_b/plan_b_unit_field.gd:244) 绘制单位图像、阵营弧线、属性徽标、网格、气泡和尾巴，绘制命令增长有直接源码依据。
- Physics mean 同时从14.119ms升到25.278ms。D 的位置事件回调同步运行在 B 发出 signal 的调用栈中；D 6eb1fc 已复用 Packed 数组，回调成本仍需用 profiler/function counters 拆分。
- 6b384425 的日志出现 `Invalid polygon data, triangulation failed`，栈位于 `PlanBUnitField._draw_group_bubble_tails()`。D 后续提交 `df90acbb` 加了零面积保护；该修复只有 headless UI smoke 结果，D3D12 matched post-D profile 尚未提供。
- 因此当前数据能确认 B/D 集成存在 CPU 侧回退，但不能把25.278ms physics归因给单一 B 函数。GPU均值仅小幅增加，说明纯GPU瓶颈的证据较弱。

## 下一步最小验证建议

1. 先取得 D `df90acbb` 合入后的同场景 matched 96 profile，确认绘制错误消失并分离 D 侧影响。
2. 在 E 已有 probe 中只加计数，不改游戏逻辑：neutral/faction neighbor queries、每次 topology rebuild 的成员数、每秒接触对数和空间桶候选数。不要用总体FPS代替函数耗时证据。
3. 单独验证 neutral-scan patch：相同正式场景、相同 seed/96人口，检查 `_get_neighbor_units()` 调用数下降，同时对比感染、逃避、结群和 contact smoke。
4. neutral-scan通过后，再单独测试有序Unit列表复用；每次只改变一个B热点，记录同口径 physics/process/wall/GPU数据。

## 已保存的未应用实验

neutral-scan patch 只绕过中立单位的无用邻域查询；它仍走原 `_get_steering()` 中立早退、目标决策计时器和物理游荡。配套 smoke 夹具在目标半径内放置一个静止中立单位，并检查该单位的 `_get_steering()` 收到空邻居数组，其他单位保留真实邻域搜索。该 patch 从先前未提交实验恢复到独立文件，当前 B 源码保持 commit `1fc3249e`，本诊断未应用 patch，也未运行测试。
