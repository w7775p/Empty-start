## 4. 给总控的产品缺陷反馈

**D-EXPORT-01：普通导出模式接受 TEST_ONLY 工作簿并写入正式来源目的地。**

- 当前 `tools/export_game_data.py` 只检查 `--test-only` 模式需要工作簿标记。省略此 flag 后，同一带标记工作簿会被普通模式接受。
- 为避免触及正式表，实际复现将当前导表脚本原样复制到临时根目录的 `tools/`，将现有唯一 Tier 模板复制到该目录的 `data/combat_stage/tier_catalog.tres`，再执行临时导表脚本 `--input <现有 tests/fixtures/data_export/test_only_data.xlsx 的绝对路径>`，省略 `--test-only`。
- 临时导表进程 **exit 0**；临时 `data/source_tables/02_主播关卡.csv` 被创建，且包含 `test_level_01`。本仓库正式 data 未修改，复现目录已自动清理。
- 这是生产导表入口的来源隔离缺口。当前测试保护的是有 flag 的测试通道，无法据此宣布两个方向都安全。没有添加已知必败的测试来掩盖此产品责任，也没有修改导表实现。
- 建议导表负责人在普通模式拒绝显式 TEST_ONLY 工作簿，然后用同一临时目录案例验收拒绝退出及无正式目的地产物；是否回填 known_traps 由有权限的负责人决定。
