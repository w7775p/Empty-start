# Plan B V0.4 · 观众棋子复读感染 PK · 独立 Godot 原型规则

状态：**核心交互已由策划确认；三类属性的正式名称与克制方向、240 秒到时结算尚未确认；下列数值全部为原型试算值。** 本文为 PB-01～PB-05 的共同参考。更改核心已确认规则须回报策划。

## 核心循环
**煲煲为了赢直播 PK，选择本场尚未说过的预制话语并点击一名中立观众，让该观众开始复读；棋子自主移动、碰撞并感染其他观众；玩家再发表新话语，通过信徒间的真实碰撞让旧信徒逐渐改口，场上谁的复读者更多，PK 就逐渐朝谁移动，PK 达到 100% 后进入原有六选一矛盾击破。**

- **一个棋子是一名观众**；玩家说的话本身不生成棋子。发言必须选择当前中立观众，选择的那个棋子即时成为第一名信徒。
- 玩家仅从预制话语池选句。同一个 `word_id` 本场只允许主动发表一次；棋子可以重复复读已发表话语。
- 每次主动发言记录该阵营新的 `word_order`。玩家后发表的新话，由被选中棋子与已有**同阵营**棋子真实相撞时逐步传开：双方先弹开，旧顺序继承新顺序的文字及战斗属性，不改变阵营人数。传播链被消灭可能导致旧话语长期留存。对手可采用同一更新规则。
- 同阵营相撞（任何属性）只弹开与新旧话传递，绝不互相吞并；对手与我方相撞，**属性相同**只弹开；存在克制时，强势方尝试感染弱势方；带感染能力的阵营棋子能尝试感染中立棋子。中立闲聊没有主动感染能力。
- 感染成功的棋子改变 `team, word_id, word_order, battle_type, strength, traits`，继承感染者完整话语内容并继续传播；**感染事件本身不额外加 PK**。
- 对手持续自动投放预制话语和传播棋子，最终依据局势选择反击；普通阶段实时运行，没有回合暂停。
- 旧剧情倾向 `orthodox/heresy/absurd/neutral` 和新战斗属性 **是两类不同字段**；暂不重写三倾向、圣典、结局或已有四关剧情。

## 棋子运行数据
`unit_id`（唯一 ID）、`team`（neutral/player/opponent）、`word_id`（中立为空）、`word_order`、`battle_type`、`strength`（1～3）、`traits`、`position`、`velocity`、`collision_cooldown`、`age/lifespan`。静态话语配置：`word_id,text,battle_type,strength,traits,tendency,available_level`。随机规则可固定种子注入，便于复现。

## 必须可复现的运算
1. `publish_word(word_id, neutral_unit_id)`：检查当前战斗、预制词池、未使用、冷却、中立身份。成功后只转换被点击的中立棋子，**不创建新棋子**；同句本场不可再次主动发表。
2. `update_motion(delta)`：棋子在场内游荡；对敌对且可克制目标优先追逐，对敌对且会克制自己目标回避；碰边反弹。速度、追逐范围、逃跑范围统一可调。
3. `on_contact(a,b)`：同阵营弹开并按新旧 `word_order` 接触传话；双方敌对同属性只弹开；异属性按临时测试克制表尝试感染；一方中立按感染能力决定。持续重叠需裁决冷却。
4. `relay_new_word(newer,older)`：只把同阵营较新版本传递给较旧版本，阵营人数不变；原话 ID、属性同时更新。
5. `try_convert(winner,loser)`：成功后继承完整话语、更新阵营，并发出一次转化事实；失败继续弹开，成功率可配表并固定种子测试。
6. `update_audience(delta)`：路人持续加入；老观众自然离场；总量有上限。**仅通过真实碰撞转化棋子阵营**，不可为了补路人强行把已有信徒改成中立。
7. `update_pk(delta)`：我方更多则 PK 缓慢向 100% 走；对手更多则向 0% 走。中立不加分但算总人数。由这一处更新 PK，使用旧 Tier 阈值仅作可视读数，旧命中 PK 加分/回拉在新原型战斗中不参与。

## PK 数值表达与原型候选值
`每秒PK百分点变化 = k × (我方棋子数 - 对手棋子数) / 全场棋子数`，再乘 `delta`（秒）。
- PK 初始 50%，0% 为失败，100% 为进入原有矛盾阶段；两边人数相等时不变。
- **k=0.85 PK 百分点/秒**为试算值，例如场上我方60、对手25、中立15，则每秒约增加0.298个百分点。该值和移动、接触、人口值都须 Godot 真人试玩验证。
- 当前试算参考：最多96棋子；开局76中立、2对手、0玩家；玩家发表间隔5秒；对手间隔11.5秒；基础感染率20%；碰撞裁决冷却0.7秒；自然在场约65±12秒；有空位时0.75秒补一个路人；模型场地900×490时速度上限78 px/s。真实 Godot 中央区不是同尺寸，速度必须按实际画布试调。
- 已观察到的风险：敌方过早滚雪球、中立耗尽、超过240秒僵持、文字过多遮挡。**240秒只作为测试记录上限，实际到时规则待策划确认。**

## 战斗属性与原系统衔接
- 原型允许配置临时三角克制占位标签 `type_a/type_b/type_c`；**正式类别名称及克制顺序尚未获得最终批准**。正式开发先用可替换数据，不把临时名称写死成最终内容。
- 旧 `data/source_tables/03_普通词库.csv` 有玩家话语及旧倾向/强度字段，可从其中提取临时可选池供原型测试，必须单独写入原型配置；四名对手话语按现存内容选取，先验证费米。
- `data/source_tables/08_Tier档位.csv` 保存 PK 上升/下降阈值，`21_反击技能池.csv` 有各对手 T2～T5 候选技能。这一批先保证基本对手自主发言与 PK 能打通；正式 Tier 技能变更作为后续集成任务。
- 达到100%以后仍是旧六句真假矛盾：保持原来约10秒窗口、蓄力射击和**只允许一发且最多命中一句**；正确获奖励，错误/超时仍 PK 胜利但没有击破奖励。**独立原型阶段先提供100%通知给后续接入，正式矛盾阶段不在 PB-01～PB-05 的第一批编码范围。**

## 真人验收
- 每项可运行改动单独 commit、留完成日志，提供真实 Godot 截图或录屏；脚本解析成功不代表玩法好玩。
- 一场费米 PK 从开始到 PK 0% 或100% 可演示；玩家能主动选句、点击已有中立棋子；现场可见实时传播、敌对感染、同阵营旧话改口与 PK 变化。
- 不操作、同属性、针对性换话/选人等策略可在固定种子重复验证；重点确认有策略差别、通常2～4分钟分出结果。
