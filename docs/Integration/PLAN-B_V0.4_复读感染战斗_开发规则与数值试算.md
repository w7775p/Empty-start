# Plan B V0.4 · 观众棋子复读感染 PK · 独立 Godot 原型规则

状态：**核心交互已由策划确认；三类属性的正式名称与克制方向、240 秒到时结算尚未确认；下列数值全部为原型试算值。** 本文为 PB-01～PB-05 的共同参考。更改核心已确认规则须回报策划。

## 核心循环
**煲煲为了赢直播 PK，选择本场尚未说过的预制话语并点击一名中立观众，让该观众开始复读；棋子自主移动、碰撞并感染其他观众；玩家再发表新话语，通过信徒间的真实碰撞让旧信徒逐渐改口，场上谁的复读者更多，PK 就逐渐朝谁移动，PK 达到 100% 后进入原有六选一矛盾击破。**

- **一个棋子是一名观众**；玩家说的话本身不生成棋子。发言必须选择当前中立观众，选择的那个棋子即时成为第一名信徒。
- 玩家仅从预制话语池选句。同一个 `word_id` 本场只允许主动发表一次；棋子可以重复复读已发表话语。
- 每次成功发表由 A 为双方统一分配一个全局递增的 `word_order`。玩家后发表的新话，由被选中棋子与已有**同阵营**棋子真实相撞时逐步传开：双方先弹开，旧顺序继承新顺序的文字及战斗属性，不改变阵营人数。传播链被消灭可能导致旧话语长期留存。对手可采用同一更新规则。
- 同阵营相撞（任何属性）只弹开与新旧话传递，绝不互相吞并；对手与我方相撞，**属性相同**只弹开；存在克制时，强势方尝试感染弱势方；带感染能力的阵营棋子能尝试感染中立棋子。中立闲聊没有主动感染能力。
- 感染成功的棋子改变 `team, word_id, word_order, battle_type, strength, traits`，继承感染者完整话语内容并继续传播；**感染事件本身不额外加 PK**。
- 对手持续自动投放预制话语和传播棋子，最终依据局势选择反击；普通阶段实时运行，没有回合暂停。
- 旧剧情倾向 `orthodox/heresy/absurd/neutral` 和新战斗属性 **是两类不同字段**；暂不重写三倾向、圣典、结局或已有四关剧情。

## 棋子运行数据
`unit_id`（唯一 ID）、`team`（neutral/player/opponent）、`word_id`（中立为空）、`word_order`、`battle_type`、`strength`（1～3）、`traits`、`position`、`velocity`、`collision_cooldown`、`age/lifespan`。静态话语配置：`word_id,text,battle_type,strength,traits,tendency,available_level`。随机规则可固定种子注入，便于复现。

## 必须可复现的运算
1. `publish_word(team, word_id, neutral_unit_id)`：检查当前战斗、预制词池、未使用、冷却、中立身份。成功后只转换被点击的中立棋子，**不创建新棋子**；同句本场不可再次主动发表。
2. `update_motion(delta)`：棋子在场内游荡；对敌对且可克制目标优先追逐，对敌对且会克制自己目标回避；碰边反弹。速度、追逐范围、逃跑范围统一可调。
3. `on_contact(a,b)`：同阵营弹开并按新旧 `word_order` 接触传话；双方敌对同属性只弹开；异属性按临时测试克制表尝试感染；一方中立按感染能力决定。持续重叠需裁决冷却。
4. `relay_new_word(newer,older)`：只把同阵营较新版本传递给较旧版本，阵营人数不变；原话 ID、属性同时更新。
5. `try_convert(winner,loser)`：成功后继承完整话语、更新阵营，并发出一次转化事实；失败继续弹开，成功率可配表并固定种子测试。
6. `update_audience(delta)`：路人持续加入；老观众自然离场；总量有上限。**仅通过真实碰撞转化棋子阵营**，不可为了补路人强行把已有信徒改成中立。
7. `update_pk(delta)`：我方更多则 PK 缓慢向 100% 走；对手更多则向 0% 走。中立不加分但算总人数。由这一处更新 PK，使用旧 Tier 阈值仅作可视读数，旧命中 PK 加分/回拉在新原型战斗中不参与。

## PK 数值表达与原型候选值
`每秒PK百分点变化 = k × (我方棋子数 - 对手棋子数) / 全场棋子数`，再乘 `delta`（秒）。
- PK 初始 50%，0% 为失败，100% 为进入原有矛盾阶段；两边人数相等时不变。
- **k=0.85 PK 百分点/秒**为试算值，例如场上我方60、对手25、中立15，则每秒约增加0.298个百分点。该值和移动、接触、人口值都须 Godot 真人试玩验证。
- 当前试算参考：最多96棋子；开局76中立、2对手、0玩家；玩家发表间隔5秒；对手间隔11.5秒；按强度的感染率（1级20%、2级35%、3级50%）；碰撞裁决冷却0.7秒；自然在场约65±12秒；有空位时0.75秒补一个路人；模型场地900×490时速度上限78 px/s。真实 Godot 中央区不是同尺寸，速度必须按实际画布试调。
- 已观察到的风险：敌方过早滚雪球、中立耗尽、超过240秒僵持、文字过多遮挡。**240秒只作为测试记录上限，实际到时规则待策划确认。**

## V0 补充决定：strength 和 A/B/C/D 最小接口（2026-10-17）

### strength 的唯一战斗作用
- **战斗类型先决定能否感染，strength 再决定这次是否成功。** 只有“敌我两侧存在确定克制关系、强势一侧试图转化弱势一侧”或“带感染能力的棋子试图转化中立观众”时才抽取成功率。平级敌对棋子相撞只弹开，强度再高也不会感染。同一阵营相撞传话必定成功，强度不参与。
- 感染成功率按**感染方当前复读话语的 strength** 决定；被感染者的 strength 暂时不做抵抗减算。V0 试算：strength 1 → **20%**，strength 2 → **35%**，strength 3 → **50%**。每次合法接触只判一次，受共同的碰撞冷却约束；失败弹开并保留原状态。随机数固定 seed 可重现。
- strength 暂不改变速度、寿命、PK 推进、单位数量或同阵营改口速度。复制/分裂等 traits 为单独机制，先验证 strength 独立生效；若 traits 影响一次感染的命中规则，必须写清楚并复测。
- 强度3在相同战斗类型与其他条件下比强度1更易感染，这是当前的预期差异；**持续选最高强度是否过强需要真人试玩**，不得把此 V0 数字视为正式平衡。

### 最小公开接口与唯一状态归属
1. **A / 战斗组织者**唯一拥有：本局发表顺序号 `next_word_order`（双方共用、从1递增）、双方已主动发表的 `word_id` 记录、发表冷却、PK 值、战斗开始/结束状态。双方都调用 `publish_word(team, word_id, neutral_unit_id) -> {ok, reason, word_order?}`；允许 `team=player/opponent`。每次调用先检查选中的单位仍属中立、词可用且未用过、当前能发言，再读 C 的词配置并请求 B 播种；**只有 B 播种成功**才占用该词、消耗冷却、分配并提交顺序号；失败不得消耗任何资源。A 调用 B 前可暂取候选顺序号，成功后再把计数器加一。
2. **C / 预制话语**只提供 `get_word_definition(word_id)` 等只读查询，返回`word_id,text,battle_type,strength,traits,tendency` 的**不可变值快照**，确保静态词属性只有一个配置来源；C 决定费米何时请求发言和推荐的候选词/中立单位，最后仍交 A 用同一个 `publish_word` 检查和提交。
3. **B / 棋子模拟**拥有全部棋子的运行状态；开放 `seed_unit(neutral_unit_id, team, word_definition, word_order) -> bool`、`get_faction_counts() -> {player,opponent,neutral}`、`get_unit_snapshots()`（供 D 只读显示）等最小入口。A 不能直接修改棋子字段。B 在播种、敌我感染、同阵营接触改口、出生、自然离场时产生**事实事件**，建议 `unit_changed(unit_id, reason)`、`unit_spawned(unit_id)`、`unit_despawned(unit_id)`；其中 `reason` 区分 `seed/convert/relay`。事件仅用于通知 UI/演出刷新，不通过事件增减 PK。
4. **棋子身上存完整话语的只读值快照**（含 `word_id`、文本、类型、强度、特性、顺序号）。遇到敌对感染或同阵营传话，接收方整体复制传播者快照；无需每次碰撞访问 C 的词库。静态定义由 C 管，棋子当前复读哪句话由 B 管；运行快照不得写回正式词库。
5. **A / PK 结算**在战斗持续运行期间每个物理帧或固定频率主动调用 B 的 `get_faction_counts()`，按经过秒数更新 PK，并按需发出 `pk_changed(value)`。棋子转换带来的人数变化会在下一次采样时自然体现在 PK 速率中。**D / UI**使用 B 的只读棋子位置快照绘图，使用 `unit_changed` 等事实事件更新文本与即时特效，用 A 的 PK 与人数查询更新 HUD；D 不自行维护人数真相或计算 PK。
6. 跨阵营的 `word_order` 虽全局唯一，但仅在**同阵营棋子相遇**时比较大小并决定新话传旧话；敌我碰撞始终先按类型克制处理。B 在接触传话前先判同阵营，并完整继承较新的字句与属性。

### 最小联调验证
- strength 1/2/3 在同种合法克制场景、相同固定 RNG seed 下有预期概率差异；同属性敌我碰撞不论强度都只弹开。
- player 和 opponent 使用同一发表入口，成功发表依次分配全局顺序号；重复词、无效目标、冷却中提交均失败且不增加顺序号。
- 新旧话语接触只更新接收棋子的复读快照与 `unit_changed(reason=relay)`，人数不变；感染成功改变阵营及复读属性并发出 `unit_changed(reason=convert)`。
- B 是唯一棋子状态源；A 的 PK 只按 B 真实人数和经过时间变化；D 显示的文字/人数/PK 与两者一致。

## 真人验收
- 每项可运行改动单独 commit、留完成日志，提供真实 Godot 截图或录屏；脚本解析成功不代表玩法好玩。
- 一场费米 PK 从开始到 PK 0% 或100% 可演示；玩家能主动选句、点击已有中立棋子；现场可见实时传播、敌对感染、同阵营旧话改口与 PK 变化。
- 不操作、同属性、针对性换话/选人等策略可在固定种子重复验证；重点确认有策略差别、通常2～4分钟分出结果。
