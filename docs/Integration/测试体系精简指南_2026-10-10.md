## 给总控的具体清理与冲突建议

1. **CA-12 过期数值期望。** `ca12_mouse_restore_gui.gd` 触鼠恢复断言仍为 `aim.reticle_diameter == 32`；当前正式 `aim_reticle.gd` 默认 144、`aim_reticle.tscn` 最小尺寸 144，PA-08 README 已确认视觉 96/判定 144。对应 Agent 应对齐正式规则，保留“首次按下无补 MouseMotion、中心正确”的断言。先核对短计时和触屏夹具，再归因产品缺陷。
2. **容量名称夸大覆盖。** `test_normal_repeat_capacity_independent.gd` 创建两个通用账本，没有 BarrageArea；`test_normal_and_trap_share_capacity.gd` 的对象没有陷阱类别；`test_capacity_release_resumes_generation.gd` 没有 Timer。建议删除独立账本隔离用例；共享上限/释放测试保留最低限度的账本不变量即可。真实分类由 `test_repeat_spawns_when_normal_full.gd` 与 INT-01/攻击边界负责，KT-31 的“运行中 Timer 不重启”需保留真实 Timer 证据。
3. **复读计划局部赋值。** `repeat_plan_test.gd` 改局部变量 `configured_count`、`settled_tier`，没有实际改 CombatStage 或生成配置；两个断言证明赋值结果。建议删去该驱动，保留 INT-01 的实际结算档位、后续新弹幕变化，以及独立寿命快照规则。无需为删除再创建新壳。
4. **INT-01 保留行为，剔除结构。** 固定 `CenterContainer` 缺失、三块 HUD 的 NodePath、精确“🔊数字”串、`_pending_items` 内部字典和数组大小，分别耦合布局、LD 展示与队列结构。优先保留暂停冻结、未满取消、一发一次、复读零收益、收益驱动 Tier、失败保留旧成果、真假矛盾与候选重叠裁决。固定规则数值应从正式规则审查，不能统统改成“>0”。
5. **导表加载检查重复。** `test_test_only_sandbox.gd` 只读继承场景属性，建议删除。CSV 转换和真实导出错误保护仍有独立价值；`test_generated_tables.gd` 六档逐字段比较跨数据来源，属于防字段漂移。Python 的“20 个产物”可缩成必要资产存在及重复/失败保持，随导出范围变化审查，避免拿数量充当产物语义。

## 三个常见误区与手工最小路线

- **headless ≠ Windows GUI。** SceneTree、Timer 或纯数据 PASS 只覆盖其逻辑。渲染、窗口缩放、焦点、纹理可见性和音频需对应平台验证，参考 KT-30/38。
- **程序注入 ≠ 物理鼠标。** `Input.parse_input_event` 进入引擎事件管线，`pressed.emit()` 直接触发信号；直接 `_input()` 加 `_charge_progress.advance()` 又绕过事件分发和实际蓄力时间。报告中分别写明方法，不能把这些叫作人工点击。KT-39 的按下后补定位会掩盖首发错误。
- **路径加载 ≠ 玩家完成流程。** load、instantiate、读取 Catalog、120 帧启动均各有局部价值。玩家流程要经历选择、失败重开、奖励、继续、终局及结局；短计时/静止弹幕/debug PK/测试卡片使该流程只能证明 TEST_ONLY 接线。

受影响的操作 PR 至少由验收人在正式 Windows GUI 手动做：进入新周目→同卡首次翻开/二次选中→回退保留→开播；移动鼠标、首发按下/蓄力/释放、未满取消→ESC 暂停/恢复→失败重开；检查一种真实胜利后的历史查看/返回/继续。窗口缩放、失焦及触鼠切换按输入改动补做。正式配置无法走到非空终局时记录停止位置与缺失参数，TEST_ONLY 双路线继续用于接线证据。记录场景、引擎、渲染后端、输入来源、实际退出码、失败描述；手工结束无应用退出码时明确写“人工关闭/无测试 ExitCode”。
